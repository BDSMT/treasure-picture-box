# 分卷解压：怎么判断一个分卷包能不能解

> 这份文档记录的是**判定依据**和当时的实测结果。改代码前先看这里，
> 免得把「为什么不能只查大小」这件事重新踩一遍。

## 一、问题的形状

分卷包是「一个大文件按字节切成 N 段」，N 个文件拼起来才是一个完整归档。
用户下载时常见的三种破损：

| 破损方式 | 表现 | 靠什么发现 |
|---|---|---|
| 少下了一卷 | 文件名序号有缺口，如 1、2、4 | 命名（毫秒） |
| 某一卷下到一半断了 | 文件在、大小比别的小 | 卷大小一致性（毫秒） |
| 内容有字节损坏 | 名齐、大小也对 | **只能靠 CRC**（分钟） |

第三种是隐形的。所以判定必须分层，代价从毫秒到分钟递增，
前面几层能拦掉的就不必付后面的代价。

## 二、三层判定

### 第 1 层：结构扫描（`scan` + `describe_problem`）

不需要读文件内容，只看目录和元数据：

1. **卷号连续**：1..N 无缺口。缺号 = 必然不完整，可以 100% 确定。
2. **除末卷外大小一致**：分卷工具（7z `-v`、WinRAR、HJSplit）切出来的每一卷
   都是同一个大小，只有最后一卷装尾巴、可以更小。
   所以「中间某卷比标准值小」= 那一卷没下完，也是 100% 确定。
3. **末卷不能是 0、不能比其他卷大**。

标准值取**众数**而不是平均值：有一卷坏掉时，众数仍然是正确的那个大小。

### 第 2 层：归档结构（`structure`）

调 `7z l`，让它把归档的头尾读出来。这一步对 10 GB 的分卷也只要一两百毫秒。

它抓的是第 1 层看不见的问题：卷都在、大小都对，但拼起来根本不是一个合法归档
（比如某一卷其实是下载到的错误网页）。

### 第 3 层：内容校验（`verify`）

调 `7z t`，逐文件算 CRC32。要读完全部字节，10 GB 大约几十秒到几分钟。

**这一层不能省。** 实测：

```
# 把 7z 分卷的第 2 卷翻掉一个字节，长度保持不变
7z l test.7z.001   → exit 0，Volumes: 4        # 结构层认为一切正常
7z t test.7z.001   → exit 2，CRC Failed : big.bin
```

如果只做到第 2 层，这个包会被「成功」解压，产出坏文件。

## 三、解压时的保护

7z 遇到 CRC 错误不会立刻停，它会尽量解完再报错。所以不能直接解到目标目录。

做法：**先解到同级的临时目录 → 退出码为 0 才改成正式名字 → 否则整个删掉**。

这样用户在失败后看到的文件夹里，什么都不会多出来。

## 四、支持的命名

| 命名 | 家族 | 第 1 卷 | 交给 7z 的文件 |
|---|---|---|---|
| `name.7z.001` / `name.zip.001` | 纯字节切分 | `.001` | 第 1 卷 |
| `name.001` | 同上，无内层扩展名 | `.001` | 第 1 卷（类型靠魔数嗅） |
| `name.z01` + `name.zip` | 老式 PKZIP 跨卷 | `.z01` | `name.zip`（它才是最后一卷） |
| `name.part1.rar` / `part01.rar` | WinRAR 分卷 | `part1` | 第 1 卷 |
| `name.rar` + `name.r00` | 老式 RAR 多卷 | `.rar` | `name.rar` |

### 一个必须防的误判

`photo.2024` 和 `archive.001` 在正则眼里长得一样。

规则：**数字补零的**（`001`、`0001`）直接认；**不补零**的（`2024`）
必须同目录下真的存在 `.001` 才认。宁可漏判，也不要把用户的照片
当成第 2024 卷去扫描。

## 五、为什么内置 7z.exe

- RAR 是专有格式，唯一能可靠解压和校验的实现是 unRAR 代码，只有 7-Zip 带。
- 7z 自己的 LZMA/BCJ2 多流编码也没必要重写。
- `7z t` 是唯一能对全部格式做逐文件 CRC 并报告「哪个文件坏了」的现成工具。

体积代价：`7z.exe` 574 KB + `7z.dll` 1.9 MB，压缩进发布包约 +1.1 MB。
放在 `runtime/7z/`，用 `datas` 而不是 `binaries` 收集 ——
binary 会被 PyInstaller 改写依赖、可能被改名，而 `7z.exe` 必须和同目录的
`7z.dll` 保持原名才能加载。

许可：7-Zip 主体是 LGPL，RAR 解压部分受 unRAR license 限制（允许解压，
不允许用它开发 RAR 压缩器）。许可原文随包放在 `runtime/7z/LICENSE-7-Zip.txt`。

## 六、验证覆盖

`tools/test_splitvol.py`（59 项）逐项构造并断言：

- 完整 7z / 完整 zip 分卷 / 裸 `.001` / 单文件归档
- 缺中间卷、缺第 1 卷
- 中间卷截断成一半
- 单字节损坏（结构层放过、内容层抓住）
- 命名误判防护、五种命名风格解析
- 解压失败后目标目录无残留、重名不覆盖

`tools/grab_split.py`（23 项）验界面：不完整时**解压按钮根本不存在**，
清单里缺卷占位、无「停用」类残字。
